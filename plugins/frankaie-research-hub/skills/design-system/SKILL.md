# 品牌設計系統管理器（Design System Manager）

這是一個**工具型 skill**，不是角色。它解決一個具體問題：
HUB 的品牌規範過去只寫在文件裡，每次出稿都靠「記得遵守」，跨 skill 產出必然逐漸走鐘。

本 skill 把 LYCANDER 的視覺變數固定成一份**可直接貼進畫布／程式碼的清單**，
並提供出稿前的稽核表，讓 `visual-team`、`animation-designer`、`listing-optimizer`、
`web-engineer` 的產出共用同一套值。

> 原則：規範不是拿來讀的，是拿來**套**的。任何一個顏色或字級，只要在這份清單上找不到，就是錯的。

---

## 何時用

- 開一張新的設計畫布、要先鎖定品牌變數。
- 手上有多份視覺稿（主圖／A+／落地頁／社群），要檢查一致性。
- 品牌要改版（換主色、換字體），需要一次盤點所有受影響的產出。
- 交稿前跑品牌合規稽核。

## 需要的輸入（缺的會主動問，不自行編造）

1. 品牌主色 / 輔色（HEX）；沒有就先給既有素材讓本 skill 反推並標 `【需查證】`。
2. 中英文字體（品牌指定字型；無授權字型時給 fallback 方案）。
3. 適用場景（電商主圖 / A+ / 落地頁 / 社群 / 包裝）。
4. 目標市場（TW / US / JP / EU）—— 影響字體 fallback 與對比度需求。
5. 既有規範文件或設計稿（有的話）。

## 運作流程

1. **盤點現況** — 收集既有素材，抽出實際在用的顏色、字級、間距，列出偏離值。
2. **收斂成變數** — 每一類收斂到最少可用數量（色彩建議 ≤ 8 個語意色、字級 ≤ 6 階）。
3. **命名與語意化** — 用途導向命名（主色 / 強調 / 警示 / 中性 N），不是「藍色 1」。
4. **無障礙檢查** — 文字與底色對比度須達 WCAG AA（一般文字 4.5:1、大字 3:1），未達標直接標紅。
5. **輸出可套用清單** — 產出下方表格 ＋ 一段可貼進畫布或前端的變數定義。
6. **稽核既有稿** — 用合規檢查表逐項打勾，列出違規項與修正值。

## 實例演練（Worked Example）

**輸入**：65W GaN 充電器要做 Amazon US 主圖套組 ＋ A+ ＋ 官網 hero，希望三處視覺一致。

**輸出（節錄）**：
- 收斂前盤點出 11 個藍色（來自不同輪次的稿），收斂為 `brand.primary` 1 個 ＋ `surface.raised` 1 個。
- 對比度檢查：原本淺灰說明文字對白底僅 2.9:1，**未達 AA**，調深至符合 4.5:1。
- 字體 fallback：日本市場沿用同一字型會缺漢字，補上日文 fallback 後才可用於 JP。
- 稽核官網 hero 舊稿：間距為 13 / 27px 等非系統值，改為 12 / 24（4 的倍數）。
- 實際 HEX 與字型名稱未由使用者提供者，一律標 `【需查證】`，不臆造品牌色。

## 與團隊串接

- **上游**：`visual-team`（劉承軒的品牌視覺方向）、`animation-designer`（單兵創意方向）決定「長什麼樣」，本 skill 負責固定成變數。
- **平行**：`listing-optimizer` 的 A+ 版面、`web-engineer` 的落地頁實作，直接引用同一份變數表。
- **下游**：稿件送 `validation-panel` 驗證前先跑合規稽核；交付前過 `quality-gate`。
- **記憶**：變數表版本寫進 `planning-with-files` 的 findings 檔，避免每次重新盤點。

> 提醒：本 skill **不發明品牌色與字體**。使用者未提供的值一律標 `【需查證】` 留空，
> 不以「看起來像」推定品牌資產；對比度數值須實際計算，不憑印象宣稱通過。
