## 1. 事實基準

### 1.1 Remotion 是什麼

React 程式化影片框架：用 TSX 描述每一幀，透過 headless Chromium 逐格截圖後編碼成 mp4。
官方 skills bundle 含 **12 個 skill**：`remotion-best-practices`（router）、`remotion-create`、
`remotion-markup`、`remotion-studio`、`remotion-render`、`remotion-maps`、`remotion-captions`、
`remotion-saas`、`remotion-interactivity`、`remotion-docs`、`remotion-multimedia`、`remotion-upgrade`。

結構特徵（實際 clone 檢視）：
- description 全為 3–6 個英文字（23–47 字元），無觸發關鍵字清單、無 `⚠️` 分界標註
- 共 161 個 md、3.4 MB；`remotion-best-practices/` **實體巢狀複製了其餘 11 個 skill**
- **不是 Claude plugin**（無 `.claude-plugin/plugin.json`），官方安裝路徑為
  `npx skills add remotion-dev/skills` → 落在 `.claude/skills/`
- 執行面需求：Node.js + `npx create-video@latest` + `npm i` + `npx remotion studio` / `render`

### 1.2 本 repo 現況

- `plugins/frankaie-research-hub/skills/` 下 33 個 skill **全部為純 markdown persona**，
  非 `.md` 檔僅 `plugin.json`。全 repo **沒有 package.json**，零 Node 工具鏈。
- 影片能力現況：`ad-hook-writer` 產 hook 與 0–3s 分鏡 → `animation-designer` / `visual-team`
  產分鏡表與規格清單 → **斷點** → 人工剪輯／外包 → mp4。
- `visual-team/SKILL.md:137` 已承諾產出「短影音成品（MP4、含字幕）」，
  但 `animation-designer/SKILL.md:179` 自陳「本技能負責 brief、分鏡與 prompt」，製作外包。
  **這是一張目前跳票的支票。**

### 1.3 執行環境實測結果

| 項目 | 結果 |
|------|------|
| `npm i remotion @remotion/cli @remotion/renderer` | ✅ 249 packages / 20 秒 / **249 MB** |
| 系統 ffmpeg 依賴 | ✅ **不需要** — Remotion 4.x 自帶 Rust compositor（內含 ffmpeg，約 26 MB） |
| 預設 render | ❌ 失敗：`remotion.media` 被 egress proxy 擋（403），無法下載 chrome-headless-shell |
| 指定 Playwright headless shell 後 render | ✅ **成功產出合法 mp4** |
| 2 秒 720p（60 frames） | ✅ 14.2 秒 / 124 KB |
| 10 秒 1080p（300 frames） | ✅ 17.5 秒 / 638 KB（比即時還快） |
| ffprobe 驗證 | ✅ H.264 1280x720@30fps、含 AAC 音軌 |
| 繁體中文 | ✅ 系統 WenQuanYi Zen Hei 可渲染，無豆腐字（字型品質陽春，成品建議自帶 Noto Sans TC） |

**必要設定**（環境變數 `REMOTION_BROWSER_EXECUTABLE` 實測無效，只有 config／CLI flag 有效）：

```js
// remotion.config.js — 動態解析，避免寫死 Playwright 版本號
const base = '/opt/pw-browsers';
const dir = fs.readdirSync(base).filter(x => x.startsWith('chromium_headless_shell-')).sort().pop();
Config.setBrowserExecutable(`${base}/${dir}/chrome-linux/headless_shell`);
```

> 注意：必須用 `chromium_headless_shell-*`，用完整版 `chromium-*/chrome-linux/chrome` 會
> `Failed to launch the browser process`。系統 lib（libnss3 等）Playwright image 已備妥。
> `fonts.gstatic.com` 回 404，**字型檔勿依賴執行期下載，應直接進版控**。

`npx create-video@latest ... && npm i`，`remotion-studio` 會起長駐 server。
本 repo 33 個 skill 誤觸最壞只是「答錯人」，Remotion 誤觸會在 repo 內建 npm 專案。
**`hub-router` 現行仲裁表 6 條規則對此零覆蓋。**

### 專家 B｜技術可行性（實測）

| 構面 | 分數 | 理由 |
|---|---|---|
| 技術可行性 | **5** | 不是「只能寫程式碼」，是實測完整產出合法 mp4，效能優於即時；自帶 ffmpeg 消除最大系統依賴疑慮 |
| 環境相依風險 | **3** | 能跑，但吊在 Playwright 版本化路徑上，官方自動下載退路被 egress 封死；已驗證 glob 動態解析可緩解 |
| 授權風險 | **2** | 4 人門檻極低且外包併計人頭，商業組織幾乎必然落入付費區；source-available 而非 OSS |

### 專家 C｜商業價值

場景適配度：

| 場景 | 適配 | 說明 |
|---|---|---|
| 電商短影音（Reels/TikTok 廣告） | **低** | 勝負在實拍 hook 與情境感，Remotion 產出會像「會動的 PPT」 |
| A+ content 動態 | **低** | A+ 主體仍是靜態模組，需求頻率低 |
| 規格動畫（GaN 功率分配／體積對比／溫度曲線） | **高（甜蜜點）** | 純資料驅動、無需實拍、改規格只改 props |
| 多語系批次（TW/US/JP/EU） | **高（碾壓性優勢）** | 同 composition 換 JSON 出 4 語；GUI 工具改 4 語＝重做 4 次 |
| 多尺寸 9:16 / 1:1 / 16:9 | 中高 | responsive layout 要自己寫，但做一次省 3 倍工 |

判斷式：**只有「同一支要出 ≥8 個版本」或「內容是純數據」時 Remotion 才贏。**
估算：一年 4–8 個 SKU × 4 語 × 3 尺寸 ≈ 100–200 次 render，但只源自 4–8 個 composition。

替代方案：Adobe `video_render`／`animate_design`、Canva brand template dataset 批次、
Figma `export_video`、外包剪輯。**Remotion 對這些都不是取代關係，是補位**；
真正取代的只有「外包做規格說明動畫」與「Canva 批次的動畫天花板」。

使用門檻（決定性因素）：HUB 使用者是品牌經營者非工程師。現有 skill 成本是
「打一句中文 → 拿一份表格」；Remotion 是「維護 React 專案 → 寫 TSX → render」。
預測：第一次有 agent 在旁會成功且有 wow 感；三個月後要自己改一句文案再 render 大概率放棄。
**不做封裝的長期使用機率估 20–30%，做了封裝可拉到 60–70%。**

| 構面 | 分數 | 理由 |
|---|---|---|
| 實際需求強度 | **3** | 斷點真實存在，但非 Remotion 不可的只有「規格動畫＋多語批次」窄帶 |
| 加值／非重複性 | **4** | 「程式化、可版控、逐幀確定性」在現有 Adobe/Canva/Figma MCP 找不到對應品 |
| 預期使用頻率 | **2** | composition 只有幾個；非工程師中長期高機率退回 Canva |
| 投入產出比 | **3** | 省下外包費一年約 NT$5–15 萬，但要先付 1–2 天封裝＋持續維護＋授權費 |

## 5. 前置條件與重評觸發點

達成以下條件後重評，預期可將 D1 / D5 / D6 各拉高 1–2 分，總分進入 4.0+ 區間：

### 必要前置條件

1. **確認授權** — 盤點共同操作 Remotion 的總人數（含外包）。
   若 ≥ 4 人，取得 Company License 預算簽核。**未確認前不得導入。**
2. **確定安裝路徑** — **不要** vendored 進 `plugins/frankaie-research-hub/skills/`。
   改用 `npx skills add remotion-dev/skills` 裝在實際影片專案的 `.claude/skills/`（CI 實測全綠）。
3. **隔離執行環境** — 影片專案獨立子目錄並自帶 `package.json`，不污染 repo 根層。
   `remotion.config.js` 以 glob 動態解析 Playwright headless shell 路徑。

### 建議配套（決定使用率的關鍵）

4. **產線封裝（1–2 天）** — 預建吃 JSON 的 composition 骨架：4 語字型（Noto Sans TC/JP 進版控）、
   品牌色 token、3 種尺寸 layout，包成 `npm run render -- --data spec.json` 單指令入口，
   讓使用者永遠不需要看到 TSX。**不做這層就會是典型的「裝了但用不到」。**
5. **HUB 側薄橋接** — 在 HUB 內加一支符合 Pattern B 的橋接 skill，
   把 `animation-designer` 的《創意製作包》分鏡表欄位映射成 composition props。
6. **補 `hub-router` 仲裁規則** — 新增「影片／render／mp4」precedence：
   分鏡創意 → `animation-designer`；完整素材專案 → `visual-team`；實際程式化渲染 → Remotion 專案。
7. **修正 `visual-team` 的跳票承諾** — 「短影音成品（MP4、含字幕）」改成有實作後盾的說法。
8. **擴充 `quality-gate`** — 現行 rubric 不含 mp4 與程式碼，需補影片產出的審查項目。

### 重評觸發點

以下任一成立時，重跑本評估：

- 出現「同一支影片需 ≥ 8 個語系／尺寸版本」的實際專案（D1 直接上修）
- 完成前置條件 1–3，且有 1–2 天工程餘裕做條件 4（D5 上修）
- 確認公司規模 ≤ 3 人或已購入 Company License（D6 上修至 4–5）

### 過渡期替代方案

在上述條件成立前，多語系批次需求先用 **Canva brand template + dataset 批次**
（`get-brand-template-dataset` / `create-design-from-brand-template`）撐住；
規格動畫需求先走 Adobe `animate_design`／外包。
